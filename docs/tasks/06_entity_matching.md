# 第 6 组多源实体匹配任务书

## 目标和边界

模块 ID 为 `entity_matching`，代码目录为 `modules/entity_matching/`。系统判断左右数据源中的记录是否指向同一实体，不负责发现整张可连接表。

## 输入和输出

- 输入：左表、右表、可选候选对和可选匹配真值。
- 输出：`[{left_id,right_id,score,is_match,evidence}]`。
- 左右表必须明确稳定主键；禁止使用行位置代替业务 ID。
- `task_type` 固定为 `entity_matching`。

## 两种基础方法

1. 规则方法：文本规范化后进行精确、Jaccard、编辑距离或字段加权匹配。
2. 统计方法：Fellegi-Sunter 风格权重或基于相似度特征的逻辑回归。

DeepMatcher 和 Ditto 用于后续扩展讨论；第一阶段先保证简单方法、候选生成和评价正确。

## 第一阶段数据集

- 构造左右各不超过 100 行的客户或商品表。
- 人工加入拼写差异、缩写、字段缺失和非匹配近邻。
- 提供 `gold_pairs.csv`，包含 `left_id`、`right_id` 和匹配标签。

## 评价

- 对候选对报告 pair precision、recall 和 F1。
- 如果实现 blocking，分别报告候选召回率和候选数量缩减比例。
- 展示字段级相似度作为 evidence，并记录阈值。

## 最小交付

- 两种方法使用同一候选对和真值运行。
- 页面上传左右表、选择字段与阈值、展示匹配对和证据。
- 测试重复主键、未知字段、空候选、无匹配和全匹配情况。

## 不做事项

- 不把高相似度自动等同于确定同一实体。
- 不承担第 7 组的整表 Union 或 Join 检索。
- 不在测试集上选择最终阈值后再报告同一测试集性能。
