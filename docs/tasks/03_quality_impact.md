# 第 3 组数据质量影响任务书

## 目标和边界

模块 ID 为 `quality_impact`，代码目录为 `modules/quality_impact/`。系统比较数据质量问题和清洗策略对下游分类任务的影响，不建设通用自动清洗平台。

## 输入和输出

- 输入：带目标列的表格、数据划分、污染或清洗配置、下游分类器配置。
- 输出：`{quality_metrics:{},downstream_metrics:{},comparisons:[...]}`。
- `metadata` 记录数据划分、随机种子、分类器和依赖版本。
- `task_type` 固定为 `quality_impact`。

## 两种基础策略

1. 简单策略：删除缺失行、常量填充或删除重复记录。
2. 统计策略：均值、中位数或众数插补，并对重复和异常值执行明确规则。

至少固定一个简单分类器用于公平对比；如比较多个分类器，保持同一数据划分和随机种子。

## 第一阶段数据集

- 构造一份不超过 500 行的二分类小表，包含数值和类别特征。
- 从干净版本按比例注入缺失、重复或标签噪声，保留污染位置真值。
- 后续引入公开数据集前，先提交来源、许可和划分说明。

## 评价

- 数据质量指标：缺失率、重复率、污染率或与干净表的差异。
- 下游指标：accuracy、precision、recall 和 F1，优先报告 F1 变化。
- 所有策略使用同一训练测试划分，报告多随机种子均值时同时报告波动。

## 最小交付

- 原始干净、污染后、策略一和策略二四种条件的可复现实验。
- 页面可以选择污染程度、清洗策略和随机种子，并展示对比表。
- 测试目标列缺失、单一类别、无法划分和不可序列化模型输出。

## 不做事项

- 不宣称一次实验能证明某种清洗方法普遍最好。
- 不让测试集信息参与训练或插补参数拟合。
- 不把模型对象直接保存到实验 JSON。
