# 第 4 组数据依赖发现任务书

## 目标和边界

模块 ID 为 `dependency_discovery`，代码目录为 `modules/dependency_discovery/`。系统发现或验证函数依赖并定位违反记录，不自动修复数据。

## 输入和输出

- 输入：单个 CSV、最大左部列数、最小支持或允许违反阈值。
- 输出：`[{lhs:[...],rhs:'...',support:...,violations:[...],evidence:{...}}]`。
- 违反记录使用稳定 `row_id` 标识。
- `task_type` 固定为 `dependency_discovery`。

## 两种基础方法

1. 小规模穷举：枚举限制大小的 LHS 和 RHS，通过分组验证 FD。
2. 层次搜索：实现 TANE 风格的逐层候选生成和基本剪枝，记录搜索候选数。

Metanome 与 HyFD 用于理解平台和算法设计；第一阶段只需在小数据上正确、可解释地实现基础版本。

## 第一阶段数据集

- 构造不超过 200 行的表，明确包含如 `zip -> city`、`student_id -> name` 的真 FD。
- 注入少量违反记录并保存 FD 真值与违反行真值。
- 数据卡记录每条依赖为什么成立以及如何注入违反。

## 评价

- 有 FD 真值时报告 FD precision 和 recall。
- 对每条已知 FD 报告违反组数、涉及行数和定位正确性。
- 比较候选数、运行时间和不同最大 LHS 大小的变化。

## 最小交付

- 两种方法在同一人工数据上发现至少两条真 FD。
- 页面展示 LHS、RHS、支持、违反数和具体证据。
- 测试空列、常量列、重复列、最大 LHS 非法和完全无违反数据。

## 不做事项

- 不自动修改违反记录。
- 不依赖第 2 组修复模块。
- 不在小型教学实现中承诺处理任意宽表或大规模数据湖。
