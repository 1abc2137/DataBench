# 第 8 组数据库查询分析任务书

## 目标和边界

模块 ID 为 `query_analysis`，代码目录为 `modules/query_analysis/`。系统在受控 PostgreSQL 测试库中采集和比较查询执行计划，不连接生产库，不执行任意写入 SQL。

## 输入和输出

- 输入：只读 SQL、测试库连接配置和实验策略。
- 输出：`{plan:{},execution_time_ms:...,diagnostics:{...},comparison:{...}}`。
- 连接凭据来自环境变量或本地 `.env`，不得写入代码或实验 JSON。
- `task_type` 固定为 `query_analysis`。

## 两种基础实验策略

1. 默认计划基线：使用 `EXPLAIN (FORMAT JSON)` 收集估计行数、成本、连接顺序和算子。
2. 对比策略：增加或移除测试索引，或在受控会话中调整一个 `enable_*` 优化器设置，再比较计划和执行表现。

Bao 和 JOB 用于理解查询优化研究与工作负载；第一阶段不要求训练学习型优化器。

## 第一阶段数据集

- 使用自建 PostgreSQL 测试 Schema、生成脚本和少量可控数据。
- 提供至少 5 条包含过滤、连接和聚合的只读查询。
- 第一阶段先用自建数据验证安全和指标；使用 JOB 子集前补充来源、许可、加载步骤和资源需求。

## 评价

- 使用普通 EXPLAIN 时报告估计成本、估计行数和计划结构差异。
- 使用 `EXPLAIN ANALYZE` 时报告实际时间和估计行数误差，并明确它会执行查询。
- 对索引前后或设置前后使用同一数据和查询，记录缓存、重复次数和 PostgreSQL 版本。

## 最小交付

- 安全解析并拒绝明显的 INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE 和多语句输入。
- 页面默认只运行普通 EXPLAIN；启用 ANALYZE 前显示明确确认说明。
- 至少比较一种索引或优化器设置对 5 条查询的影响。
- 测试危险 SQL、连接失败、超时、空 SQL 和不支持的计划节点。

## 不做事项

- 不连接生产数据库或保存真实凭据。
- 不默认运行 `EXPLAIN ANALYZE`。
- 不把一次运行时间差异直接归因于优化器优劣，必须说明缓存和环境影响。
