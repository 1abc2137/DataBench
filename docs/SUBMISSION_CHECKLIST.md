# DataBench 模块提交清单

提交前逐项确认。未通过项应写入提交说明，而不是删除检查项。

## 方案和边界

- [ ] 模块 ID 和题目边界与 `core/registry.py` 一致。
- [ ] 已提交最小可运行方案，写明输入、输出、两种方法、评价和第一阶段数据集。
- [ ] 没有实现任务书明确排除的内容。
- [ ] 没有直接修改 `app.py`、公共注册或其他组目录。

## 数据

- [ ] 至少有一份几秒内可运行的小型示例数据。
- [ ] 数据卡写明来源、许可、格式、主键、标签和预处理。
- [ ] 不包含敏感数据、凭据或未经许可的大型数据。
- [ ] 数据没有真值时，没有报告准确率、F1、Precision@k 或 Recall@k。

## 方法和结果

- [ ] 至少实现两种适用的基础方法或实验策略。
- [ ] 每种方法位于独立算法目录并具有合法 `algorithm.json`。
- [ ] 页面只通过 `execute_algorithm` 调用算法，不直接导入特殊依赖。
- [ ] 每种方法说明原理、参数、限制和适用条件。
- [ ] 返回 `AlgorithmResult`。
- [ ] `predictions` 字段、主键和示例已经说明。
- [ ] 结果可以由标准 `json.dumps` 序列化。
- [ ] 随机方法固定或记录随机种子。

## 页面和实验

- [ ] 页面包含输入、参数、运行、结果和错误提示。
- [ ] 页面可以从统一入口打开，不修改 `app.py`。
- [ ] 使用 `save_experiment` 保存数据集标识、配置、指标、元数据和预测结果。
- [ ] README 命令可以复制执行。
- [ ] 页面说明与实际按钮和输出一致。

## 测试

- [ ] 正常小样例测试通过。
- [ ] 空数据或非法输入测试通过。
- [ ] `AlgorithmResult` 合同测试通过。
- [ ] 实验保存和重新读取测试通过。
- [ ] 指标至少有一个手工可核对案例。
- [ ] 本组测试通过。
- [ ] `uv run python -m pytest -q` 全量测试通过。

## 提交说明

- [ ] 列出新增依赖、用途和版本。
- [ ] 独立 uv 算法已提交 `pyproject.toml`、`uv.lock` 和 `.python-version`，且没有提交 `.venv`。
- [ ] 列出修改文件和原因。
- [ ] 写明复现命令、预期输出和已知限制。
- [ ] 公共接口变更已有批准的 Issue 链接。
