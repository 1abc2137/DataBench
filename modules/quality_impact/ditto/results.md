# Ditto 实验结果

## 一、训练

| 项 | 值 |
|---|---|
| 训练 / 验证 / 测试对 | 2,232 / 279 / 279 |
| 语言模型 | `distilbert-base-uncased` |
| epochs | 3 |
| batch size | 8 |
| max_len | 128 |
| 验证集 F1 | 0.996 |
| 测试集 F1 | 0.989 |

正负样本各占一半；正样本来自“同一电话”的记录对，负样本为不同电话的随机配对。

## 二、推理

对全量数据中“同一电话”的候选对打分（阈值 0.5）：

| 项 | 值 |
|---|---|
| 候选对 | 1,395 |
| 判定匹配 | 1,381（98.9%） |
| 重复组 | 1,327 |
| 涉及行数 | 2,675 |

## 三、下游影响

同一划分（训练 9,005 / 测试 3,002）、同一模型（logreg）：

| 清洗方式 | 保留行数 | F1 | Accuracy |
|---|---:|---:|---:|
| 不处理 | 9,005 | **0.653** | 0.581 |
| 整行比对去重 | 8,997 | 0.653 | 0.581 |
| 键碰撞（telephone） | 8,224 | 0.626 | 0.567 |
| Ditto 去重 | 7,982 | **0.618** | 0.565 |

## 四、结论

1. **三种重复清洗都让 F1 下降**，与 CleanML 论文“重复清洗多为不显著（S）或负向（N）”一致；
2. Ditto 删得最多（比键碰撞多 242 行），F1 也最低——**检测越激进，误删越多**；
3. 原因：Ditto 把同一电话下的多对判定为匹配后，并查集做传递合并（A≈B、B≈C ⇒ A、B、C 同组），可能把不同门店并入同一组，造成过度删除；
4. 该数据上的“重复”本身高度相似，模型 F1 接近 1，说明任务简单；真实场景的实体解析更难。

## 五、可调项

- 阈值 0.5 → 0.6/0.7：减少误合并，观察 F1 是否回升；
- 阻断策略：目前按电话分块，可改为名称前缀分块，避免共用电话造成的错误候选；
- 合并规则：用“最大团”替代并查集传递闭包，抑制链式过度合并。
